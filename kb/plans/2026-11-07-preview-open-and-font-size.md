# 预览文件用默认应用打开与文本字号设置

## PRD

### 背景与目标

用户在远端文件预览窗口中，希望直接使用本机默认应用打开文件，并能在设置中调整文本预览字号以便阅读。用户已明确要求先写计划、再派 Codex 执行。

### 功能与交互

- 每个文件展示栏顶部右侧，在下载按钮右边增加“用默认应用打开”按钮，采用向应用跳转的图标，与现有按钮尺寸、样式一致。
- 点击后通过 macOS 原生打开机制，将当前文件的完整本地缓存交给系统选择的默认应用，不弹另存对话框、不选择指定应用。文本、图片、音频和无法内置预览的文件均适用。
- 文件未下载完成或下载失败时按钮不可用；打开失败给出可见错误反馈。多栏时只打开按钮所属文件。
- 打开的是本地缓存副本；外部编辑不会自动上传到远端。提示文字或文档清楚说明这一点。
- 设置窗口增加全局“文本预览字号”：默认 12 pt，8–32 pt，步进 1 pt，显示当前值。保持等宽字体；只改变文本正文，不改变文件标题、目录树、截断提示或其他预览类型。
- 字号调整立即影响已打开的所有文本预览，自动保存，重新启动后保留；不依赖是否选中或配置了远端机器。

### 范围与验收标准

不加入字体家族选择、外部编辑回传、默认应用管理或新快捷键。

1. 按钮位于下载右边，图标、悬浮提示、禁用状态正确。
2. 文本和图片分别在系统默认应用打开，路径与原文件名正确；多栏打开对应文件。文本超过预览截断上限时打开完整文件。
3. 二进制已下载时可尝试打开；系统无法打开时显示错误，不报告虚假成功。文件路径含空格、引号等字符仍正确。
4. 设置字号可调，边界不能越界，多窗口即时同步，重启后保持；其他预览与机器配置自动保存不受影响。

## Tech Design

### 现状

- `GaplessPaste/UI/PreviewWindow.swift` 的 `PreviewWindowModel.downloadedFiles` 保存每个远端路径对应的本地缓存 URL。`canExport(_:)` 判断本地下载是否就绪，`saveFile(_:)` 从缓存复制到另存位置，`showFeedback(_:)` 提供短暂反馈。
- `PreviewPane.header` 末尾目前依次是刷新、复制和下载，下载回调是 `onSave`，标识为 `preview-save`。
- `PreviewPane.content` 的文本分支使用 `.font(.system(.caption, design: .monospaced))`。截断只影响预览内容，打开应使用完整缓存 URL。
- `GaplessPaste/UI/SettingsWindow.swift` 的 `SettingsView` 是机器列表与详情的分栏，下方有 footer；`SettingsModel` 负责机器配置校验与自动保存。

### 方案与数据

- app 层为模型加入打开操作，将 `downloadedFiles[node.id]` URL 交给 macOS 原生默认应用打开。优先用 `NSWorkspace` 的原生 URL 打开 API，语义等价于系统 `open <path>`；如用 `/usr/bin/open`，必须用独立 argv，不经 shell 插值。不要添加文件类型到应用的硬编码映射。
- 打开操作检查缓存可用性并在操作入口处理系统错误，复用反馈与日志；无默认应用或文件已消失时可见失败。避免为单个系统调用引入通用服务框架。
- `PreviewPane` 新增打开回调，由父视图绑定对应 node。按钮使用 SF Symbol `arrow.up.forward.app`（构建与实机确认可用），标识 `preview-open`，帮助文字“用默认应用打开（本地副本）”，可用条件沿用下载完成状态。
- 字号属于本机显示偏好，保存在 UserDefaults，建议键 `previewTextFontSize`，不改远端机器的 config.json。通过共享键和 `@AppStorage` 让设置和所有 PreviewPane 同步。
- Core 增加小型字号规则值类型，集中默认值 12、最小 8、最大 32、步进 1 和非法持久值归一化规则；非有限值回默认，有限越界值钳制边界。不引入 AppKit。
- 设置增加机器分栏外的“文本预览”区域，使用原生 Stepper 或等价紧凑控件显示字号。即使没有机器也可调整。控件加 `settings-preview-font-size` 标识，不绑定机器配置保存流程。
- 文本正文使用显式字号的等宽字体，截断提示继续沿用现有字号。尽量保持用户选中文本、滚动和当前文件，不能因字号变更重新下载文件。

### 风险与边界

缓存被外部应用编辑后，本地预览与远端可能不同；沿用现有手动刷新缓存机制，并明确本地副本语义。系统默认应用启动与前台切换需真实验收，不能用 mock 替代。设置窗口较小尺寸下要检查新增区域与底部状态栏不会挤压或遮挡。

## 执行与验收结果（2026-11-07）

在当前 `master` 分支执行，没有创建分支或 worktree。

实机发现并修复了计划之外、直接影响字号功能的问题：原 SwiftUI `Text` 在 32 pt 下布局接近 512 KB 的多行正文会长时间阻塞主线程。验收脚本先复现 AX 超时，`sample` 确认停在 SwiftUI 布局；正文改用原生只读 `NSTextView` 的按需布局，保持等宽字体、选择能力和滚动容器。修复后同一文件在 32 pt 下可正常响应并打开。没有缩减原有 512 KB 预览上限。
