# 菜单摘要优先布局与右下角传输状态徽标

## PRD

### 背景与目标

当前菜单顶部直接展示包含完整文件名的上次操作字符串，长名称会撑宽整个菜单；时间行额外缩进，视觉基线不一致。菜单关闭后也看不到操作是否仍在进行。

用户已通过交互稿选择 C「摘要优先」＋③「右下角徽标」，并明确要求上传／下载只用纯上箭头／下箭头，不带底部托盘。用户已确认继续实施，无需重新选型。

目标是让菜单稳定、紧凑地说明最近一次操作，让用户在菜单关闭时也能看见传输方向、完成或失败反馈。

### 已确认的设计

| 项目 | 决定 | 来源 |
| --- | --- | --- |
| 菜单 | C：结果在第一行，类型、方向、相对时间在第二行；文件名进入详情 | 用户选择 |
| 状态图标 | 保留应用主图标，在右下角叠加徽标 | 用户选择 |
| 方向徽标 | 发送使用纯 ↑，接收使用纯 ↓，均无托盘或凹槽 | 用户明确修订 |
| 完成与失败 | 完成显示 ✓；失败显示 ! | 已确认 Mockup |
| 反馈时序 | 成功约 2 秒后恢复待机；失败到查看详情或重试后解除提醒 | 已确认 Mockup 中的方案参数 |
| 进度 | 不展示虚构百分比；进行中轻微动画，减少动态效果时使用静态箭头 | 已确认 Mockup |
| 本地设计稿 | 仅保存在项目临时目录，不进入版本控制 | 用户最新要求 |

### 功能与交互

1. **顶部摘要**：两行共用文字左基线，状态符号独占图标列，不用空格凑缩进。约 320 pt 的正常菜单宽度是设计目标；摘要中的文件名、错误正文和长机器名不能把整个菜单撑宽。机器名优先保留可识别部分，剩余省略。摘要不是可执行菜单项，鼠标经过不出现动作项式高亮。
2. **结果与方向**：发送显示「已同步到远端」或「已上传到远端」，接收显示「已接收到本机」；次行展示例如「图像 · 本机 → mini · 14 小时前」。多个文件展示数量，文本展示类型而非正文。进行中用「正在同步到远端…／正在接收剪贴板…」；接收内容尚未知时可暂用「剪贴板」。失败摘要简短，原因进入详情。
3. **详情**：提供可通过键盘和鼠标进入的「查看传输详情…／查看失败详情…」。可读取完整文件名、方向、内容类型、大小或文本字数、时间、失败原因；有多个文件时列出全部文件。没有源文件名的图像／文本不虚构文件名。不展示文本剪贴板正文。完整文本可选择、换行或滚动，不反向撑宽主菜单。
4. **空状态**：尚无记录时显示「还没有传输记录」与开始传输的指引；不伪造上次成功记录。
5. **菜单栏反馈**：待机只有原图标；操作启动立即出现方向徽标，约 300 ms 后仍在进行才开始轻微循环动画。完成或失败立即停止循环动画。成功约 2 秒后移除徽标，但菜单中的记录保留；新操作即时覆盖旧反馈，旧计时器不得清除新操作状态。
6. **失败确认**：打开失败详情才清除菜单栏提醒，只打开主菜单不等于确认。确认后仍保留失败记录和合法的重试入口；新操作清除旧提醒。取消、空剪贴板或不支持的平台等拒绝不得伪装成成功，也不得残留进行中图标。
7. **已有业务行为**：普通上传、快速上传、拖拽上传和双向剪贴板同步都进入相同反馈体系。busy 期间禁用上传／同步，预览仍可用。保留原有拷贝远端路径、重试、配置、更新等入口与语义。
8. **部分成功**：现有目录上传可能文件已落盘，但后续远端剪贴板注入失败。必须保留可获取的远端路径，准确显示「已上传，剪贴板写入失败」及详情，不能伪装为剪贴板同步成功，也不能新增会导致重复上传的重试行为。可使用 ! 提醒部分成功。非 macOS 远端的既有路径降级仍为预期完成。
9. **可访问性**：单色图形随系统深浅／选中态适配；状态不依赖颜色。状态按钮提供包含方向和结果的可访问性描述；系统减少动态效果开启时不做循环动画。

### 不做的事

不新增历史列表、传输队列、持久化最近记录、用户配置项、全局热键；不改 SSH 协议、重命名、上传目的地、现有平台降级规则。不实现 A／B 或其他三个图标方案的原生切换器。此次不发版、不推送、不创建新分支或 worktree。

### 验收标准

- AC1：超长文件名、多文件、长机器名及长错误信息不撑宽顶部摘要；两行文字对齐，C 布局不直接列出文件名。
- AC2：所有既有传输入口都在菜单关闭时即时更新徽标；↑／↓均无托盘，右下角不裁切、不移动其他菜单栏项目。
- AC3：发送和接收方向正确，成功在相关业务步骤完成后出现，约 2 秒后恢复待机；快速连续任务不会被旧计时器清除状态。
- AC4：失败停动画、保留提醒；查看详情解除提醒但保留失败记录；重试可用性与现有业务保持一致。
- AC5：详情可读取长名称、多文件、类型、大小／字数、失败原因；键盘可达，不暴露文本正文。
- AC6：空状态、取消、远端为空、不支持的平台、目录上传部分成功均有真实、无悬挂的状态。
- AC7：深浅背景、菜单选中态、1×／2×符号尺寸、减少动态效果和可访问性描述均可用；拖拽目标和原菜单点击行为不回归。
- AC8：现有单测、构建通过，完成原生 UI 验收；记录真实验证结果与未能验证的限制，提交实现与文档。

### 现状与修改位置

- `GaplessPaste/UI/StatusMenuController.swift`：使用 `NSStatusItem.squareLength`，初始化时设置 `arrow.up.doc.on.clipboard`；仅在 `menuNeedsUpdate` 中重建菜单，直接输出 `statusLine`，时间前加了全角空格。保留 `NSStatusItem` 与原生 `NSMenu`，不要整体改成 popover。
- `GaplessPaste/App/AppState.swift`：`isBusy`、`statusLine`、`lastFinishedAt`、`lastRemotePaths`、`hasRetryableFailure` 与 `retryAction` 分别记录结果。主要异步入口为 `transfer(machine:directory:payload:)`、`sync(machine:content:)` 和 `syncClipboardFromRemote(machine:)`；`prepareAndTransfer`、`prepareAndSync` 还包括取消与内容拒绝。
- `transfer` 的图像注入失败已有「上传已成功，重试可能重名」的处理；不要把这类警告简单归入可重传失败。检查抛出异常与非零退出码两条路径，保证真实结果与已有副作用一致。
- `GaplessPaste/UI/DropPanel.swift`：`StatusItemDropDetector` 覆盖在 status button 上并转发鼠标，徽标绘制不能拦截其 hit testing 或破坏按钮尺寸。
- `GaplessPasteCore/Sources/GaplessPasteCore/DisplayFormatter.swift` 与对应 Tests：已有相对时间／大小格式化，可复用。Core 不得引用 AppKit。
- `GaplessPaste/App/DebugHooks.swift`：现有 DEBUG 自截图、预览钩子，可扩展可重复的状态 fixture 与图标导出，不能让 Release 暴露测试控制。
- `GaplessPaste/App/DockPresence.swift`：若新增普通详情窗口，使用 `track(_:)` 接入窗口存续行为。

### 方案与数据

新增小型、纯 Swift 的结构化传输展示模型／状态机到 Core（最终类型名由执行者确定）。它记录操作标识、操作种类、方向、机器／目录、内容类型、文件名列表、可用大小／字符数、起止时间、结果与错误／警告。记录可以在接收内容解析后补齐；不存储完整文本正文或图像数据。仅内存，不改配置或做迁移。

将「最近操作记录」与「短暂图标反馈」分开：成功徽标超时或失败确认不能抹掉结果记录。用操作 ID 或代次标识隔离过期计时回调，支持可注入时间的纯状态转换测试，避免用真实 sleep 验 Core 逻辑。

不要从中文 `statusLine` 解析状态。若旧字段还被 DEBUG 或其他代码引用，保留单向派生兼容层或同步迁移调用者，避免两套可变状态各自更新。

### AppState 与通知链路

用一个集中的 MainActor 状态变更入口更新展示模型，再通过显式回调／轻量观察通知 StatusMenuController。当前不是 ObservableObject，无需为本次任务全局改造状态管理。开始、结束、失败、拒绝／取消、内容补齐、提醒确认都走同一事件路径。

图标刷新不得依赖重新打开菜单。状态变更与 `isBusy` 更新顺序要一致；菜单正展开时，安全更新摘要与动作启用态，避免在 tracking 中粗暴重建导致焦点／选择丢失。到达成功前确认相应传输／注入／本地写入均完成。保持既有重试动作和远端路径来源。

取消或拒绝时退出 busy 并恢复合理静态状态，可保留上一条有效记录；不得凭空创建成功结果。目录上传部分成功需要独立 warning 或等效可表达结果，不能仅修改提示字符串掩盖真实状态。

### 摘要与详情 UI

以自定义不可交互的 `NSMenuItem.view` 或等效原生布局承载 C 的两行摘要，约 320 pt、统一基线、次要文字使用 secondary label 颜色。按实际可用宽度省略机器名；不要以字符串长度猜测宽度。完整错误不进入摘要。其余动作保持标准菜单项，新增可交互控件必须具备 accessibilityIdentifier。

详情采用可复用的原生详情窗口：通过标准菜单动作打开，内容可选取、换行、滚动，并显示该次记录的稳定快照；避免新传输启动时把正在阅读的失败信息覆盖。打开失败记录的详情时，只确认对应操作 ID 的提醒。按现有 `DockPresence` 规则管理窗口。该选择是实施方的技术决定，Mockup 已允许原生详情窗口，不要求复刻 HTML 内联折叠。

### 徽标绘制与动态效果

保留主图标，在固定 status button 内合成右下角小徽标：发送 `arrow.up`、接收 `arrow.down`、成功 `checkmark`、失败／警告 `exclamationmark`。使用实际可用的 SF Symbols 或等效清晰绘制；箭头不能使用 `.to.line`、托盘／盒子组合。最终图像适配 template 着色，1×／2× 绘制避免细线模糊，角落留出空间防裁切；不要覆盖按钮交互层。

开始即显示静态方向，持续超过约 300 ms 后可轻微改变徽标透明度，主图标保持稳定；成功／失败立即停止循环。系统减少动态效果开启时保持静态。空闲期间不跑轮询或持续动画。成功恢复计时约 2 秒，必须可取消并以当前操作 ID 校验；菜单 tracking 中也应正常完成计时。状态按钮提供完整的可访问性标签／帮助信息。
