# 菜单栏设计对比

直接用浏览器打开 `index.html`。HTML、CSS、JavaScript 均为本地文件，无依赖、无构建步骤、无外部资源请求。所有操作都是模拟，不触发 SSH 或读写剪贴板。

## 方案

| 菜单 | 设计 | 取舍 |
| --- | --- | --- |
| A · 紧凑双行 | 第一行结果与文件，第二行方向、大小、时间 | 贴近原菜单，信息密度较高 |
| B · 分层摘要 | 结果与时间 / 文件 / 方向与大小 | 推荐；增加一行换取清晰层级 |
| C · 摘要优先 | 结果 / 内容类型与方向，文件名进入详情 | 最精简，确认文件名需要展开 |

| 图标 | 设计 | 取舍 |
| --- | --- | --- |
| ① 旁边圆点 | 蓝、绿、红状态点，同时改变符号形状 | 显眼，额外占用横向空间 |
| ② 整体变色 | 对整个状态符号着色 | 最醒目，需验证壁纸和选中态 |
| ③ 右下角徽标 | 原图标叠加方向、对号、感叹号 | 保持应用身份，但小尺寸下拥挤 |
| ④ 单色切换 | 默认符号 / 发送 / 接收 / 对号 / 警告 | 推荐；形状清晰，操作期间暂时弱化应用身份 |

各组可独立组合。预览支持浅色／深色、超长文件名、多个文件、文本、无记录、五种操作状态、减少动态效果及图标放大。点击「播放一次传输」演示 2 秒传输、2 秒成功反馈、恢复待机。直接点击某状态则保持该状态，便于比较。

## 设计边界

- 320 px 的预览宽度对应原生实现的约 320 pt 目标宽度；它不是 Apple 规定的菜单宽度。窄屏预览可以收缩。
- 所有顶部信息共用文字基线；状态符号独占图标列。状态信息不作为可点击的禁用菜单项高亮。
- 文件名根据渲染宽度做中间省略，完整名称通过详情与悬停提示访问；纯文本不显示正文。
- 成功定义为完整流程结束，包括需要的剪贴板写入；没有字节进度时不展示百分比。
- 成功约 2 秒后清除图标反馈，菜单记录保留；失败到查看详情或重试才清除提醒。新任务优先，旧任务的恢复计时器必须取消。
- 原生实现建议对不足约 300 ms 的任务避免启动循环动画。此稿播放的是固定时长示范，不实现真实传输速度判定。
- 菜单展开时采用系统前景色；颜色不是唯一状态通道。正式版须支持 VoiceOver 状态描述和系统减少动态效果设置。
- SVG 是形状近似稿。正式实现仍使用 SF Symbols/template image，并验证真实屏幕、菜单选中态和拖拽交互。
- 详情在 HTML 中用内联展开表达信息层级；原生可使用标准子菜单或详情窗口，最终交互在实施时确定。

## 依据

- [Apple：Menu bar extras](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar#Menu-bar-extras)：优先符号与菜单，系统着色适配深浅背景及选中态。
- [Apple：Inclusive color](https://developer.apple.com/design/human-interface-guidelines/color#Inclusive-color)：重要信息不能仅依赖颜色。
- [Apple：Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)：反馈真实进度；不定进度表示操作仍在执行。

推荐 B＋④ 是针对本项目的判断，尚未得到用户选择，不代表已确定的开发规格。
